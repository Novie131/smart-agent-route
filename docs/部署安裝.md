# smart-agent-route 部署安裝

## 需要的檔案

- 整個 repo(或 `smart-agent-route.plugin`;沒有 `.plugin` 時 `install.sh` 直接用 `plugins/smart-agent-route/`)
- `install.sh`(僅 CLI / VS Code 需要)

---

## 系統需求

| 項目 | 需求 |
|---|---|
| 作業系統 | macOS / Linux / Windows(`install.sh` 需 WSL 或 Git Bash) |
| Claude Code | 2.1.271 以上(`omitClaudeMd`);一行安裝指令需 2.1.275 以上 |
| 指令 | `unzip`(僅從 `.plugin` 安裝時)、`python3`(context 提醒用,缺少時安靜停用) |
| 方案 | 需能使用 Opus、Sonnet、Haiku 三種模型 |

檢查與更新:

```bash
claude --version
claude update
```

**版本太舊會靜默失效** —— 不報錯,但 `model` 欄位被忽略,所有 subagent 跟著主對話跑同一個模型,分層等於沒開。這是最難察覺的故障模式,裝完務必驗證。

## 安裝

### Cowork(桌面版)

點 `.plugin` 檔的安裝按鈕。裝一次,所有對話都能用。

### Claude Code CLI + VS Code 擴充

**兩者共用 `~/.claude/`,裝一次兩邊都生效。**

在 repo 根目錄執行(或把 `install.sh` 與 `smart-agent-route.plugin` 放同一個目錄):

```bash
bash install.sh
```

會把 agent、skill、hook 複製到 `~/.claude/`(`agents/*.md`、`skills/<名>/`、`hooks/smart-agent-route/`),名稱不帶命名空間(`worker`、`/handoff`),不需要 marketplace 或 `/plugin install`。安裝項目記在 `~/.claude/.smart-agent-route-installed`;同名的自己的檔案不會被覆蓋。**hook 不會自動啟用**:腳本不改 `settings.json`,結尾會印出片段,要自行貼進去。重開 Claude Code 後生效;更新就重跑一次。

其他模式:

```bash
bash install.sh --agents-only   # 只複製 agent(hook 與 skill 不會生效)
bash install.sh --link          # 用符號連結裝 agent、skill、hook,改 repo 立即生效(hook 需自行貼進 settings.json,腳本會印出片段)
bash install.sh --uninstall     # 移除(不動記憶資料夾)
bash install.sh --with-explore  # 另裝 Haiku 版 Explore 到 ~/.claude/agents/(不覆蓋既有檔)
```

只想試用當次 session,不安裝:

```bash
claude --plugin-dir ./smart-agent-route.plugin
```

## 裝完即可用，完整功能執行 route-setup

裝完就能用，不必手動設定。想要完整功能（狀態列、自動壓縮門檻、Haiku 版 Explore、claude-memory 記憶庫），執行 `/smart-agent-route:route-setup`（install.sh 安裝是 `/route-setup`）。它一項一項說明「做什麼 → 影響 → 怎麼還原」，一次只問一項、可略過；寫 `settings.json` 一律只碰 `statusLine` 與 `autoCompactWindow`，已有值不覆蓋，寫前備份。沒做過 route-setup 時，session 開始會提示（最多 3 次）。

下面各節是它在做的事，也可以手動做。plugin 本身不能改你的 `settings.json`，這是設計限制。

### 0. (選用)context 狀態列與壓縮點

狀態列顯示 `模型 │ ctx 95k │ 提醒 100k │ 壓縮 120k`(8 萬以下綠、提醒門檻以下黃、以上紅)。plugin 不能設定主狀態列,只能由你的 settings 指定:

- 用 `install.sh` 安裝:加 `--with-statusline`。檔案不存在就建立;已有 `statusLine` 不覆蓋,只印建議片段;沒有時先備份成 `settings.json.bak-<時間>` 再只加這一個鍵。
- 手動:貼下面片段(路徑只適用 install.sh 安裝;以 plugin 安裝的使用者請用 `/smart-agent-route:route-setup`，它會把 statusline.py 放到 `~/.claude/smart-agent-route/statusline/` 這個固定位置)。

```json
"statusLine": { "type": "command", "command": "python3 ~/.claude/hooks/smart-agent-route/statusline.py" }
```

建議 `"autoCompactWindow": 153000`:扣掉約 33k 的 buffer 後約在 12 萬自動壓縮,在 10 萬提醒之後留 2 萬緩衝寫 handoff;壓縮後 SessionStart hook 自動帶回 handoff,不需手動 /clear(33k 是作者機器的實測值、不確定是否固定,寫入後請用 `/context` 確認 Autocompact buffer 與壓縮點約 120k;有 `modelSettings` 逐模型覆蓋時要一併看)。

### 1. 設定主對話模型

```
/model opus
```

或寫進 `~/.claude/settings.json`:

```json
{ "model": "opus" }
```

沒設的話,分層的第一層等於沒開。

### 2. 建記憶庫（進階選項）

沒有 `claude-memory/` 時，記憶退回 Claude Code 的 auto memory，一樣可用。`claude-memory/` 的好處是可進 git、跨環境共用。

```bash
mkdir -p <你的資料夾>/claude-memory/{topics,kb,web}
```

再把 plugin 內的 `skills/route-setup/templates/MEMORY.md` 複製（或由 route-setup 代勞）到 `<你的資料夾>/claude-memory/MEMORY.md`。

**三個環境要指向同一個資料夾:**

| 環境 | 接法 |
|---|---|
| CLI | 在該資料夾底下開 session |
| VS Code | 加進工作區 |
| Cowork | **每次開新對話時連接進來** |

Cowork 這條是唯一需要重複做的動作,忘了連就等於失憶。

建議用 Obsidian 開這個資料夾當 vault —— 同一個位置就是 agent 讀寫處、你的檢視介面、與各環境的連接目標。

## 驗證

```
/agents
```

應出現 `worker`、`worker-hard`、`bulk`、`librarian`、`harvester`(`install.sh` 安裝時重開 Claude Code 即可;marketplace 安裝則先 `/reload-plugins`,名稱會帶前綴 `smart-agent-route:`)。

用 `install.sh` 裝但沒出現的話,先檢查 `~/.claude/agents/` 底下有沒有那五個 `.md`;只想要 agent 可用 `bash install.sh --agents-only`(代價是 hook 與 skill 不生效)。

## 受限環境

如果你的帳號屬於 Team 或 Enterprise 組織,管理員可能透過 managed settings 限制以下項目,導致部分功能無法運作:

| 限制 | 影響 |
|---|---|
| `availableModels` 允許清單 | subagent frontmatter 的 `model` 欄位若指向清單外的模型會被擋,分層失效 |
| plugin 強制啟用/停用政策 | `--plugin-dir` 無法覆寫被管理設定鎖定的 plugin |
| 關閉 auto memory | `memory` 欄位失效 |

**auto memory 被關閉的情況下**,改走「連接資料夾裡的 `claude-memory/`」那條路即可 —— `worker` 本來就優先走它,不受影響。

**模型被限制的情況下**,把 agent frontmatter 的 `model` 改成組織允許的模型,或整個拿掉(拿掉會跟隨主對話模型,失去分層但仍可用 context 隔離省 token —— 那本來就是最大的一筆)。

檢查方式:`/model` 開啟選單看有哪些可選,或 `/plugin` 的 Errors 分頁看載入錯誤。

## 更新

重跑 `install.sh` 即可:清單內的項目會被更新,你自己的同名檔不會被動。Cowork 則重新點一次新的 `.plugin`。

**兩邊都要更新。** 版本不一致時行為會不同,而且很難察覺 —— 你會以為 agent 不穩定,其實是兩邊在跑不同版本。

### 從 tiered-agents(0.7.0 以前)升級

0.8.0 起改名為 smart-agent-route。舊版不會自動移除,兩者並存時每個 agent 會出現兩份,要先移除舊版:

- marketplace 安裝:`/plugin uninstall tiered-agents@tiered-agents`,再 `/plugin marketplace remove tiered-agents`,然後照上面重新安裝
- `install.sh` 安裝:`rm -rf ~/.claude/skills/tiered-agents`(新版 `install.sh` 偵測到舊版時會提醒;`--uninstall` 會一併移除)

---

## 移除

```bash
bash install.sh --uninstall
```

不會刪除記憶資料夾,知識庫會留著。
