# Handoff

**對話是草稿,記憶是筆記本。** 要留下的寫進 handoff.md,對話就能隨時 `/clear`;下一個對話從筆記接手,不用重讀整段舊對話。

## 寫在哪裡

依序,用第一個成立的:

1. 專案目錄有 `claude-memory/` → `claude-memory/handoff.md`(新 session 開始時 plugin 會自動帶入它)
2. 有 auto memory 目錄(系統提示裡會寫明位置)→ 該目錄的 `handoff.md`,並確認該目錄的 `MEMORY.md` 有一行指向它:`- [交接筆記](handoff.md) — 新對話先讀:目前進度與下一步`
3. 兩者都沒有 → 告訴使用者筆記無處保存,建議建立 `claude-memory/`,不要自行選位置

## 格式

只記**現況**,不寫流水帳。固定四段:

```markdown
## 目前任務
<在做什麼、做到哪一步>

## 已完成與已修改的檔案
<檔案路徑 + 一句話說明改了什麼>

## 下一步
<具體到下一個對話能直接動手>

## 未決問題與使用者做過的決定
<決定要附理由;理由比結論更難重建>
```

- 已有 handoff.md → **改寫成現況**,不是在後面追加。已完成且不影響後續的項目刪掉
- 超過 60 行就精簡
- 值得長期保存的知識(踩過的坑、環境事實)不放這裡,寫進 `claude-memory/` 的主題檔或 `MEMORY.md`。handoff 只管「這件事接下來怎麼接」

## 寫完之後

提醒文字若說明已設定自動壓縮,就只照它的指示用一句話告知(壓縮後 hook 會自動帶回筆記,不需要手動處理),不用給指令選單。否則在回答結尾依當下情況,給使用者一句可直接複製的指令:

- 事情已告一段落 → `/clear`;新對話會從 handoff.md 接手
- 做到一半 → `/compact 保留<替使用者寫好要保留的決定與進度>`
- 後半段多是除錯或探索雜訊 → `/rewind` 選<指出從哪一則訊息開始>,再按 Summarize from here

不處理的話,接近 context 上限時會自動壓縮,時機和重點都不是自己選的。

不要替使用者決定清空,也不要因為寫了筆記就停止回答原本的問題。
